# HTML 呈现基准

本 skill 的界面基准是用户在 2026-11-05 指定的“推理优化选题视图”，入口 `粗方向.html#/coarse`。完整原件原样保存在 [assets/reference/粗方向.html](../assets/reference/粗方向.html)，SHA-256 为 `c9b7c69f028932dd5705bcbccbe27ab43a7cb0865ba3e81c98251238382646ba`；manifest.json 保存大小和用途。它是首要模板，必须能打开核对，不能被本说明或截图代替。

该页的排版、四级导航、筛选和下钻方式另适配到 `assets/survey.html`、`survey.css`、`survey.js`，供通用构建器填入本项目数据。适配不授权简化原布局或交互。构建不依赖外部个人路径或原本地服务；完整模板随 skill 一起复制即可。

基准只约束呈现与交互；其论文、数量、年份、来源名单、模型范围、对象分类、分组数及阅读结论都属于原项目，不能复制为新项目事实。分类仍依据本项目检索并按工作流确认。它也不把本 skill 扩展为选题打分或 idea 生成。

## 页面与交互

| 视图 | 应保留的结构与行为 |
|---|---|
| 起点 | 研究情况/对象与范围；按领域分组的来源链接；覆盖、阅读与下载说明折叠。不要用大幅论文总数、场景卡片和导出入口替代研究起点。来源分组写在 source.group，不硬编码会议名单或等级。 |
| 场景及中间节点 | 顶部标题与数据截止、四项主导航；统一筛选面板；当前路径；“01 存量”的水平分池条形图、图例与始终可见的数据表；“02 增长”的分池年度视图。点击图或表的分类名称继续下钻；“查看论文”直达当前父组。 |
| 对象/方法导航页 | 沿用当前场景/父组的筛选与级联选择，直接浏览论文。对象页到对象层；方法页可继续任意深度。分类图与列表两种入口都通往同一批论文。 |
| 论文列表 | 标题链接、正式来源/年份、分类路径、实现/训练属性；摘要或初筛解读、归属依据和实际阅读范围折叠。当前组搜索和全库搜索分开，范围明确；分页不丢失筛选。 |
| 全文拆解 | 只有实际存在 analyses 时才显示入口。共同输入画一次，各方法并排呈现，保留条件、证据及一跳关系；继续沿用已有精读组件。 |

**四项主导航始终是“起点—场景—对象—方法”。** 覆盖情况、下载和待确认提示是附属信息，不取代导航或另建一套分组工作台。用户另有明确要求时再调整。

筛选面板沿用参考页的两组单选胶囊（适用领域的实现、训练）、论文池选择、折叠的“分类与统计”说明及全库搜索。非模型领域可隐藏不适用的属性，但主导航和分类方式仍适用。未知属性保留在“全部”，不伪造“免训练”或硬件结论。

## 阶段与证据状态

- 分组待确认：用 `taxonomy-proposal.json` 在同一套图、表、面包屑和列表里预览，显著标“待确认”；不能把提案写成确认决定，也不能为等确认而隐藏对象/方法。确认后才迁移至正式分类数据。
- 某分支尚未细分：保留导航及已知路径，显示现有论文与简短状态；不发明子类、机制或精读结果。
- 评测/建模是阅读类型。若未给其方法路径，保留在父组并在图下明确显示参考数与入口：父组总数＝子组合计＋父组参考数。不要捏造“评测”干预对象来凑数。
- 年度收录分布、可比较的增幅和无法比较的状态分开配置。筛选深度不齐时，可以保留两张年度卡并显示暂缓理由，不能为了外观一致补造曲线、增幅或宣称领域增长。默认仅做描述性分布。

## 视觉基线

沿用参考页已有变量与组件：浅色 `#f9f9f7`、深色 `#0d0d0d`、最大内容宽 1160px、桌面内边距 30px 24px、14px 正文、22px 页标题；筛选卡/图表卡 12px 圆角、细边框、轻背景；克制的蓝色链接与正式池，灰色预印本段；年度两卡在宽屏并排且共用纵轴，小屏堆叠，图下给数据表。颜色服务于池或分类，含义不跨视图偷换。

不要另套首页大卡片、仪表盘 KPI、大片装饰或长开场说明。参考页中的旧版竞争度/热度部件不属于本 skill 输出目标。

## 验收

1. 从起点进入场景，点击场景到对象，再到方法组和论文；对象/方法导航可见、上下文正确，面包屑可返回父组。分组提案走相同路线。
2. 用同一筛选条件核对图、表、论文列表数量；父组参考单列时核对分母与余项。全库搜索能跨分支；当前组搜索不跨分支。
3. 年度两池共用尺度、时钟各自明确，未知时间不入年度曲线，未完整年度不计算全年增幅；不可比较时留理由。
4. 用两个不同领域样例构建并执行事件检查，避免把参考主题写死。检查提案投影不改写确认数据，以及错误跨场景归类被拒绝。
5. 能用浏览器时，对照基准检查场景、至少一个对象/方法组、论文页和既有精读页；检查深浅色与窄屏。结构测试、浏览器交互和视觉检查分别记录，不能互相替代。

布局调整应落在 assets，动态差异落在配置。避免项目生成脚本在 build 后再补一套字符串替换或 renderAll 包装，否则模板无法保证交付一致。
